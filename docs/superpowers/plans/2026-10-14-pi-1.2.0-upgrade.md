# Pi 1.2.0 / RPC 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify a standalone `pi-agent-rpc:0.2.0` image using the unmodified official Pi 1.2.0 snapshot.

**Architecture:** Copy the existing backend and contract packages from the Web checkout into this repository without modifying Web. Build these packages against the vendored Pi SDK, preserve protocol v1 and contract 0.1.0 unless a real protocol change is necessary, and build the runtime image from local sources rather than stale vendor artifacts.

**Tech Stack:** TypeScript, Node 22, npm, Alpine Linux, Docker Engine API, HTTP/SSE, fs-ext.

**Spec:** User-approved scope in this conversation: backend-only source ownership, Pi 1.2.0, project 0.2.0, local image build and acceptance; no registry push or deployment.

## Global Constraints

- Do not modify `/app/Pi-Agent-Web` or patch `source/upstream/pi`.
- Preserve the user's existing upstream-source replacement and unrelated changes; do not commit without permission.
- Run dependency resolution, compilation, tests, and image builds only through Docker API tools, without host mounts or privileged containers.
- Keep protocol v1 behavior compatible; report Web's existing Pi 0.84.4 handshake restriction rather than editing Web.
- No live provider credentials or paid model calls; distinguish deterministic acceptance from real-provider verification.

## Review Focus

- Concurrent CLI/RPC writes, import/fork/resume transitions, and process death must retain exclusive session ownership.
- Prompt preflight rejection versus ambiguous transport failure must not cause duplicate or lost submissions.
- SSE replay, overflow resync, disconnect, and session replacement must preserve event lifecycle semantics.
- Missing/incorrectly permissioned Secrets and unauthorized filesystem access must fail closed.
- Production image must include all new Pi workspace dependencies and use a CLI entrypoint whose SessionManager is actually protected by preload.
