# Pi 1.4.0 Adaptation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve existing RPC behavior on official Pi v1.4.0 and deliver a verified daemon-local candidate for Web joint acceptance.

**Architecture:** Retain current SDK services/runtime, version-bound lock interception and multi-stage Docker packaging. Fix shared compatibility boundaries, not endpoint-specific workarounds.

**Tech Stack:** TypeScript, Node >=22.19.0, Pi SDK 1.4.0, node:test, Docker Engine API.

**Spec:** `docs/superpowers/specs/2026-10-22-pi-1.4-adaptation-design.md`

## Global Constraints

- Official Pi revision: 4a080252f06caf63a525d7873c5d94d3c23887e0; no upstream edits.
- Docker-only installs/builds/tests. No host mounts or production data.
- Preserve protocol v1, storage/discovery/cwd/SSE/auth/locking; no new product APIs.
- No Web edits, delegation, commits, merges, pushes or deployment without authorization.
- Preserve manually supplied upstream changes; do not stash/reset/clean them.

## Review Focus

1. Lock contention during fork/import or failure must not mutate source/target without a lease (Task 1).
2. Resumed explicitly disabled/default-inactive extension tools must not reactivate (Task 2).
3. Ambiguous scopes and literal slash/colon model IDs must not silently choose another provider (Task 2).
4. Malformed tool arguments must not execute; billed total must not be recomputed from estimates (Task 3).
5. Cold restart/settings removal must preserve lookup authorization and original JSONL (Task 4).
