# Pi 1.4.0 RPC adaptation

## Approved scope

Adapt existing RPC to official Pi v1.4.0, commit
4a080252f06caf63a525d7873c5d94d3c23887e0. User approved switching the manually
cloned upstream directory to that exact tag; its nested Git worktree is clean.
Preserve protocol v1, optional project-session-discovery capability, resource
query cwd, command JSON cwd, global/project discovery, existing-file continuation,
new-storage settings, authentication, SSE and lock safety.

Only compatibility work: dependency/build provenance, version-bound lock
interception review, model selection and thinking, resumed active tools,
malformed tool-call and usage field handling, Docker regression evidence and
candidate handoff. No new classifier-image/share/telemetry HTTP APIs, upstream
edits, Web changes, architecture migration, automatic data migration, commits,
merge, release pushes or production deployment.

## Implementation calls

Keep existing SDK integration and Docker packaging. Lock interceptors remain
fail-closed for the reviewed SDK version rather than accepting arbitrary 1.x.
Compare the intercepted SessionManager and AgentSessionRuntime methods against
current baseline before changing version guards. Use SDK model scope diagnostics
rather than preemptively rejecting its newly supported ambiguous scopes.
Restored active tools must not be reactivated merely because an extension is
installed; explicit user tool commands and new-session defaults retain their
meaning. Respect defaultActive:false and subagent exclusions. Retain service
usage.cost.total even if it differs from estimated component costs; preserve
optional totalFromProvider and argumentsError through existing boundaries.

Keep project/server release version unchanged until a separate release decision;
update Pi version/revision everywhere that describes the current SDK. Historical
release notes remain historical. Do not overwrite test/latest registry tags.

## Web coordination

Web works independently: precisely admit 1.4.0 alongside 0.84.4/1.2.0; retain
protocol and required capability checks. No default tool preference writes on
cold open/refresh/reconnect. Honor supplied cost total. Kimi custom base URL
requires /v1: warn, never silently rewrite. Mock tests do not establish real
compatibility. Immutable RPC/Web candidate joint deterministic acceptance is a
release gate. Report any necessary protocol changes before implementing them.

## Verification and limits

All dependency resolution, builds and execution inside Docker API containers,
without host mounts, privileged access, production data or paid provider calls.
Run regression-first tests for changed behavior, full contract/server suites,
root/nonroot complementary permission cases, final installed-image smoke,
project session restart/media, CLI/RPC bidirectional locks, runtime and custom UI.
Exercise deterministic codemode admission/cancellation if feasible, otherwise
record an explicit verification gap. Audit production dependencies; report
findings without silently upgrading unrelated packages. No unsupported claim
that a static review or mock establishes deployed Web compatibility.
