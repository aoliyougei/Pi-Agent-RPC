# 0.4.0 — Official Pi 1.4.0 adaptation

## Changes

- Upgrade unmodified upstream snapshot to official v1.4.0,
  revision 4a080252f06caf63a525d7873c5d94d3c23887e0.
- Pin SDK peers; revalidate version-bound CLI/RPC lock interception.
- Use SDK model-scope ambiguity diagnostics and candidates, preserving explicit
  provider IDs and thinking-level pins.
- Restore SDK active extension tools without reactivating transcript-removed or
  default-inactive tools; retain explicit builtin selection and Chat only.
- Preserve malformed tool argumentsError and optional totalFromProvider;
  usage.cost.total stays authoritative. Official 1.4.0 does not natively provide
  the latter flag or OpenRouter billed-total overrides.
- Exclude local metadata and nested Git directories from Docker context.

Server/project 0.4.0, Pi 1.4.0, contract 0.1.0, protocol v1. HTTP/cwd/storage/SSE
contracts and capabilities unchanged. No classifier/share/telemetry APIs added.
No automatic session migration. Existing sessions continue in original JSONL.

## Upgrade and limitations

Use compatible Web FIRST; a Web version allowing only Pi 0.84.4/1.2.0 rejects
1.4.0. This release operation does not deploy either component.

Current production npm audit reports zero; historical sprintf-js dependency
chain versions remain unchanged, so do not interpret database changes as a fix.
Root workspace dev audit has 2 moderate Vitest findings; upstream's larger dev
install has additional findings. No runtime OS CVE audit or independent review.
No paid/live-provider, SSH/OAuth, multi-host flock, large-load or PTY retest.
Writers still require shared canonical paths and shared agent session lock dir
with working flock.
