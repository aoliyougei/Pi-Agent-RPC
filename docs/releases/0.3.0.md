# 0.3.0 — Selected-workspace session discovery

## Changes

- Selected authorized cwd adds direct `.pi/sessions/*.jsonl` discovery to the
  existing global session list, independent of settings. No recursive/sibling
  scanning, Git-root substitution, migration or project registry.
- Effective Pi sessionDir controls new storage only; continued sessions retain
  their original JSONL. Relative storage resolves against creation cwd.
- Request-local cwd hints support cold detail, state, commands, SSE, media and
  resource operations after restart, without a preceding LIST.
- Distinct files sharing a session ID fail with 409 session_id_conflict.
- Project-local CLI leases protect worktree removal.
- Optional project-session-discovery capability; required capabilities unchanged.
  Version parser accepts unknown string capabilities.

Project and server: 0.3.0; Pi: 1.2.0; contract: 0.1.0; protocol: v1.
Official upstream snapshot unchanged. No dependency upgrades; lockfile changes
only reflect root/server version metadata.

## Limits

Multiple CLI/RPC writers must share canonical paths and the agent session lock
folder with functional flock. No distributed lock guarantee for independent
agentDirs, multi-host/network storage verification or load benchmark. Browser
matrix is Web-reported, not rerun by RPC agent. No real SSH/OAuth/paid model tests.
