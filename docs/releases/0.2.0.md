# 0.2.0 — Pi 1.2.0 backend upgrade

## Changes

- Official Pi snapshot: `06a466935536f8c9bcacb2d5efc0fc021be1bdff` (v1.2.0), unmodified.
- Backend and contract sources/tests now live in this repository; Web is unchanged.
- Local backend build replaces the old vendor-package image inputs.
- Adapted getter-only system prompts to Pi 1.2 system messages and request projection.
- Updated structural SDK types for prompt dispositions and queued input results.
- Added required theme fallback colors for headless extension UI.
- Reviewed version-bound SessionManager, fork and runtime methods against Pi 1.2;
  import guards now lock the actual collision-suffixed destination.
- Retained the unbundled CLI entry to share guarded SDK identity with preload.
- Uses the official hash-pinned model catalog instead of building models.dev and
  contacting individual providers during model-data hydration.
- Server dependency undici updated 8.10.0 → 8.10.2 after reviewing its security
  release notes. Dispatcher/proxy tests pass; the changes fix TLS, WebSocket,
  retry and cache handling without changing the EnvHttpProxyAgent API used here.
- Kubernetes image reference and project/server versions updated to 0.2.0;
  wire protocol remains v1 and contract remains 0.1.0.

## Limits and deployment gates

- No Web edits, browser end-to-end test, Kubernetes rollout, registry push or Git commit.
  Web's current handshake still requires Pi 0.84.4 and needs coordinated maintenance.
- No real external model, OAuth account, remote SSH host or live push service was tested.
- The migrated backend's 411 tests are not the whole official Pi test suite.
- Dependency audit after updating undici retains 3 moderate reports in the
  mammoth → argparse → sprintf-js chain (GHSA-hp3w-g68c-fv3c). Do not blindly apply
  npm's suggested major downgrade of mammoth. No high findings remained in the
  root install at the last dependency resolution; this is not a full image/OS audit.
- Final runtime tarball installation still resolves external dependencies; base
  image tags and apk packages are not digest/version pinned.
- Review was performed by the implementer (no independent subagent available).
